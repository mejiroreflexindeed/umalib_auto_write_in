# 24 · 保留字完整列表与投稿使用说明

更新：2026-09-30。面向投稿者与录入团队。

**当前可用：旧式逐行格式，共 11 个标记。计划新增：成对格式、选填的 Pixiv 作者 ID 与自动补全。新增功能尚未实现，不要将“计划格式”作为现已可用的公告发布。** 实施范围见 [TASK-015 第 0.6 节](../tasks/TASK-015-overnight-closeout.md)。

## 1. 完整列表

使用半角方括号，字段名称按表中原文填写。当前写法为「[字段] 内容」，每个字段单独一行。

| 标记 | 用途与填写方法 | 必填性／重复规则 |
|---|---|---|
| [收录] | 表示本楼层需要收录，必须单独占一行，无需结束标记。 | 识别投稿所需；每楼建议只写一次。 |
| [标题] | 作品标题。 | 必填；重复时取首个非空值并提示。 |
| [作者] | 原作者名字，不是译者，也不是作品 ID。 | 最终审核须有作者；重复时取首个非空值并提示。 |
| [译者] | 翻译者名字；原创作品可省略。 | 解析器选填；翻译稿建议填写。重复时取首个非空值并提示。 |
| [系列] | 作品所属系列的名称，不是链接。 | 选填；重复时取首个非空值并提示。 |
| [标签] | 标签名称，用英文逗号、中文逗号或顿号分隔。 | 必填，至少一个；可重复，合并去重，保留首次出现顺序。 |
| [原作系列] | 原作系列的页面链接。 | 选填；多个链接重复写该字段，每次一个链接。 |
| [原作] | 这篇原作的页面链接。 | 选填；多个链接重复写该字段，每次一个链接。 |
| [译作系列] | 译作系列的页面链接。 | 选填；多个链接重复写该字段，每次一个链接。 |
| [译作] | 这篇译作的页面链接。 | 选填；多个链接重复写该字段，每次一个链接。 |
| [正文] | 结束资料区，从下一行开始是正文，无需结束标记。 | 当前格式可省略，但建议总是写；计划成对格式要求写。 |
| [Pixiv作者ID] **计划新增** | Pixiv 作者的数字用户 ID，或完整用户主页链接。 | **选填**，用于自动查作者名；不同 ID 冲突时交人工处理。 |

前 11 项已经存在；最后一项尚待开发。标题、作者、标签、正文缺失时，程序保留稿件并标记待补全，不会直接丢弃。没有 Pixiv ID 不增加任何必填要求；手填作者仍有效。

## 2. 目前可以直接使用的格式

### 最简模板

~~~text
[收录]
[标题] 作品标题
[作者] 作者名
[标签] 角色甲、角色乙
[正文]
这里是正文，可以写很多行。
~~~

### 含全部现有字段的示例

example.org 链接仅为格式占位，发帖时换成真实链接；没有的选填项目直接删除整行。

~~~text
[收录]
[标题] 春日约定
[作者] 原作者名
[译者] 译者名
[系列] 校园短篇集
[标签] 角色甲、角色乙，日常
[原作系列] https://example.org/original-series
[原作] https://example.org/original-1
[原作] https://example.org/original-2
[译作系列] https://example.org/translation-series
[译作] https://example.org/translation-1
[正文]
正文第一段。

正文第二段。
~~~

### 放置位置与边界

1. [收录] 可以出现在同一楼层的开头、中间或末尾附近，必须单独占一行；写在一句话中间不能触发。
2. 资料字段集中写在 [收录] 后、正文开始前。当前每字段一行，顺序不限；空行不会结束资料区。
3. [正文] 必须单独占一行，此后的文字全部按正文保留；即使出现 [作者] 或 [标签]，也不会重新读取为资料。
4. 旧格式不写 [正文] 时，第一行普通文字或已识别的 UBB 格式开头会结束资料区。为避免把正文中的 [术语]注释 当成未知字段，请使用明确分界。
5. [收录] 前的文字也会保留到正文。因此“正文在上，资料区在下”可以解析，但楼层前面的闲聊也可能进入正文。推荐直接使用上方模板。
6. 一个楼层按一份投稿处理；多个 [收录] 不会自动拆成多篇，多个楼层也不会自动合并成一篇。

### 多个标签、多人署名与多个来源

下面两行得到三个标签：角色甲、角色乙、日常；重复的角色甲只保留一次。

~~~text
[标签] 角色甲、角色乙
[标签] 日常,角色甲
~~~

- 标签只按英文逗号、中文逗号、顿号分隔；空格、斜杠、分号和井号不作为分隔符。直接写名称，不必加井号。
- 多位作者或译者可按录入团队约定写成「甲 / 乙」，但当前解析器保存成一段署名，不会自动拆分或查询多个人。
- 多来源重复写 [原作] 等字段，每次一个完整链接；不能用逗号在一个字段里拼几个链接。
- NGA 楼层地址由扫描上下文提供，不需要另写 [NGA]。
- [系列] 是名称，[原作系列]、[译作系列] 是链接，不能互相代替。

## 3. 成对格式：计划实现后使用

计划采用 **[作者]实际内容[/作者]**：结束标记多一个斜杠。不采用首尾都写 [作者] 的形式，以免与重复字段混淆。

标题、作者、译者、系列、标签、四种来源以及新增 Pixiv 作者 ID 都使用对应结束标记，如 [/标题]、[/标签]、[/Pixiv作者ID]。**[收录]、[正文] 仍只是单独一行的分界标记，不配结束标记。**

~~~text
[收录]
[标题]春日约定[/标题] [作者]原作者名[/作者] [译者]译者名[/译者]
[系列]校园短篇集[/系列] [标签]角色甲、角色乙、日常[/标签]
[原作]https://example.org/original-1[/原作]
[正文]
正文从这里开始。
~~~

计划规则：

- 成对字段可以放在同一行，字段内容也允许跨行；仍集中在 [收录] 与 [正文] 之间，不能散落在正文任意位置。
- 一个资料区统一使用旧式逐行格式或成对格式，不混用。旧式投稿继续兼容。
- 成对格式必须写独占一行的 [正文]；不要嵌套字段、交叉闭合或漏写结束标记。
- 标签分隔与去重、单值字段重复处理、每次一个来源链接，都沿用旧规则。
- 无法明确解析的内容保留原文并提示人工处理，不猜测、不吞掉正文。完全没有结束标记的文本可能被视为旧式格式，因此不要依赖软件纠正所有漏写。

**当前程序尚未支持。** 例如现在写 [作者]甲[/作者]，可能把「甲[/作者]」整段当作者，须待新版本验证后再公告启用。

## 4. Pixiv 自动获取作者名：计划新增、投稿者选填

### 用户 ID 与作品 ID 的区别

| 提供的信息 | 含义与计划用法 |
|---|---|
| https://www.pixiv.net/users/12345678 | 用户主页，数字是作者用户 ID，可填入 [Pixiv作者ID]。 |
| https://www.pixiv.net/artworks/98765432 | 插画／漫画的作品 ID，应提供完整链接到 [原作]，不能当作者 ID。 |
| https://www.pixiv.net/novel/show.php?id=98765432 | 小说 ID，同样提供完整原作链接，不能当作者 ID。 |

数字仅展示格式，不代表要查询这些账户或作品。用户 ID 定义见 [Pixiv 官方帮助](https://www.pixiv.help/hc/zh-cn/articles/235583588-%E7%94%A8%E6%88%B7ID%E6%98%AF%E4%BB%80%E4%B9%88)。

单独说“PID”容易混淆。公告使用明确名称“Pixiv 作者 ID（用户 ID）”，不增加含义不明的 [PID] 字段。

### 计划中的填写方式

**没有 ID：** 照常手填作者，不必提供 Pixiv 信息、不必启用查询。

**知道作者 ID：** 在资料区加入下列字段；作者名可以先不填，等待查询后审核，也可以同时手填名字。

~~~text
[Pixiv作者ID]12345678[/Pixiv作者ID]
~~~

也可以填用户主页：

~~~text
[Pixiv作者ID]https://www.pixiv.net/users/12345678[/Pixiv作者ID]
~~~

新版本也要支持旧式逐行写法「[Pixiv作者ID] 12345678」，不代表目前旧版本已支持。

**只有原作链接：** [原作] 中若含可识别的 Pixiv 插画／漫画或小说链接，计划支持从作品查原作者，不强制再填作者 ID。只有裸作品数字、系列链接或其他网站链接时，不猜对应作者。

### 自动补全的行为

- 录入端配置并启用查询后，识别到作者 ID 或支持的原作链接就自动尝试；投稿者无须登录录入端的 Pixiv 账号。
- 作者为空时，成功结果可预填到可编辑待审稿，仍需人工核对、批准，不会自动写入正式库。
- 已有作者名时只显示查询建议，**不自动覆盖**。多人或 ID 与作品归属冲突时交人工决定。
- 没有 ID、关闭查询、未配置账号、作品失效、网络失败或受限时，均可按原流程手填。只有作者本身为空时，才保留原有“作者待补全”。
- 作者 ID 只能帮助确认作者，不能反推出本篇是哪一件作品，不能凭它捏造原作链接。
- 获取的是查询时的 Pixiv 显示名，可能与原署名不同，以人工确认结果为准。

## 5. 不属于资料保留字的内容

- [b]、[i]、[u]、[s]、[color=…] 等属于正文 UBB 格式，不是作品资料字段；转换受现有格式白名单限制，不保证所有图片、附件或表格都保留。
- 正文的 [术语]注释 放在 [正文] 后；按现有注释约定使用时放在正文末尾连续段落，不是独立“备注”资料字段。
- [备注]、[PID]、[作者ID]、英文别名及自定义字段目前不受本表支持，写在资料区会记录为未知字段。
- 需要原样展示保留字时，放在 [正文] 后；不要在资料区中套用嵌套字段。

## 6. 公告应包含什么

公布必填的标题／作者／标签／正文、选填字段列表、半角方括号、分界位置、多个标签与来源的写法，以及一份可复制模板即可。Pixiv 功能上线后再加“作者 ID 或原作链接选填，查询失败可手填，不覆盖已有作者”。

现在公布用第 2 节旧式模板；新版本验收通过后再改用第 3 节成对模板，并明确旧格式继续兼容。不要宣称两套格式可任意混搭，也不要要求每篇必须提供 Pixiv ID。

旧公告草案见 [16 投稿格式公告](16-nga-submission-announcement-draft.md)。本说明未向 NGA 或任何外部平台发布。
