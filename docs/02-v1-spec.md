# V1 产品规格

## 模块

### Parser

- 输入：一段原始 NGA 楼层文本和可选的来源上下文。
- 触发：独立一行的 `[收录]`。
- 输出：符合 `contracts/submission.schema.json` 的 `SubmissionDraft`。
- 不猜测缺失字段，不访问网络，不写数据库。

当前临时保留字段：

- `[标题]`
- `[作者]`
- `[译者]`
- `[系列]`
- `[标签]`
- `[原作系列]`
- `[原作]`
- `[译作系列]`
- `[译作]`

字段集合仍可能在取得实际规则后调整，因此 Parser 必须保留 `raw_fields` 和未知字段。

### Inbox

建议状态：

| 状态 | 含义 |
|---|---|
| `candidate` | 已识别投稿，等待审核 |
| `incomplete` | 缺少必要字段 |
| `suspected_duplicate` | 可能与现有或 Inbox 作品重复 |
| `approved` | 人工确认可生成变更计划 |
| `exported` | 已写入候选 DB 并通过验证 |
| `ignored` | 人工忽略或不是投稿 |

状态改变必须保留时间和原因，不得覆盖原始楼层快照。

### Review UI

至少展示：

- 原始楼层与解析后的正文。
- 标题、作者、译者、系列和标签。
- 五类结构化来源。
- 缺失字段、重复字段和未知字段警告。
- 疑似重复结果。
- 大书库正文 HTML 预览。
- dry-run 数据库变更计划。

### UmaLib Adapter

只负责大书库兼容转换：

- 时间毫秒转秒。
- 作者/译者字符串规则。
- 结构化来源按最终顺序压平。
- 正文转换为安全 Quill HTML。
- 注释尾段生成。
- 标签名称解析和类型确认。

### Database Writer

- 接受已经人工批准的记录和已生成的变更计划。
- 不从网络或原始 NGA 文本直接写库。
- 默认生成候选 DB 副本。
- 支持 dry-run。
- 写入必须原子化并可验证。

## Parser 临时语法 v1

- 触发标记必须是独立一行 `[收录]`，允许行首尾空白。
- 触发标记后的连续字段块使用 `[字段名] 值`。
- 字段块可包含空行。
- 遇到第一行非字段正文后，后续所有内容均视为正文；正文中的 `[关键词]注释` 不再作为元数据字段解析。
- 单值字段重复时保留第一个非空值，并产生 `duplicate_field` warning。
- `[标签]` 可以重复；每个值按 `,`、`，`、`、` 分割，去空白并保持首次出现顺序。
- 作者和译者不按 `/` 自动拆分。
- 来源只去除字段两端空白，不在 Parser 中规范 URL。
- 未识别的字段保存在 `diagnostics.unknown_fields` 和 `raw_fields`。
- 允许标题、作者、标签等字段缺失；缺失项进入 `diagnostics.missing_fields`。
- 没有触发标记的文本输出 `parser_status=ignored`，不猜测投稿信息。

## 2026-09-08 当前语法补充

- 当前实现已支持字段块后的独立一行 `[正文]` 分隔符；该行不进入字段或正文，后续所有行进入正文，原始 raw_text 保持不变。旧无分隔符投稿继续支持。
- 已知 UBB 直接作为正文首行仍存在被识别成未知元数据的缺陷，见 Astra 复核 R07。TASK-015 必须保守修复并补版本说明；不能把 formatting 引擎支持 UBB 等同于 Parser 已正确识别正文起点。

## 必要字段

V1 将以下字段用于“信息不完整”提示，但不拒绝解析：

- `title`
- `author`
- `tags`
- `body`

## 非功能要求

- Windows 本地运行。
- Python 3.10+。
- UTF-8。
- 无运行时 AI。
- Parser 单元测试无需网络和数据库。
- 数据库 Writer 开发前必须取得脱敏真实库。
