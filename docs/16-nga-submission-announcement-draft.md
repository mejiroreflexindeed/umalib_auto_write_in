# 16 · 投稿格式公告（草案）

> 2026-09-30：本文件保留旧式公告与历史验证。全部现有字段、具体用法及计划新增项见 [24 完整保留字说明](24-reserved-fields-guide.md)。成对格式与 Pixiv 自动查询尚未上线，发布时勿混淆。

> **草案，待录入团队确认后发布。不得擅自向 NGA 发布。**
>
> 本公告只描述当前 Parser 实际支持的字段（`[标题]`、`[作者]`、`[标签]`、正文、
> 独立一行 `[收录]`）。未确认的来源优先级、标签联动、多楼层合并规则一律保留人工
> 判断，不写入公告。所有示例已于 2026-09-02 经真实 Parser 逐项验证（结果见文末表）。

---

## 简版公告（可直接复制）

```text
【投稿说明】

如需将作品收录进合集，请在楼层中这样写：

第一行单独写：[收录]
[标题] 作品标题
[作者] 作者名
[标签] 角色名

正文从这里开始，可以多行。

说明：
- [收录] 必须单独占一行才会被识别；写在句子中间不算；
- 标题/作者/标签/正文缺任意一项，稿件会进入"待补全"列表，由人工补全；
- 正文中的 [术语]注释 会原样保留，不影响投稿；
- 同一作品请勿在多个楼层重复投稿；需要修改请直接编辑原楼层，
  已收录的内容不会被自动覆盖。
```

## 详细示例（已过 Parser 验证）

### 1. 完整投稿（candidate）

```text
[收录]
[标题] 我的第一篇投稿
[作者] 某作者
[标签] 角色名

正文内容。
```

验证结果：无缺字段，进入候选（candidate）。

### 2. 缺字段投稿（incomplete，人工补全）

```text
[收录]
[标题] 缺作者的投稿
[标签] 角色名

正文内容。
```

验证结果：缺 `author`，进入待补全（incomplete），由录入人员补作者。

### 3. 正文内注释（原样保留）

```text
[收录]
[标题] 带注释投稿
[作者] 某作者
[标签] 角色名

正文[术语]注释说明。
```

验证结果：无缺字段；正文中的 `[术语]注释` 保留在正文里。

### 4. 普通回复（不会入队）

```text
大家觉得这个角色怎么样？
```

验证结果：没有独立 `[收录]` 行，只记录为普通讨论，不会进入 Inbox。

### 5. 多来源（同一作品多处投稿）

同一作品在两个楼层分别投稿时，两条会**分别**进入 Inbox（不自动合并）。
是否需要合并、以哪条为准由录入人员人工决定；程序不覆盖人工结果。

## 验证记录（2026-09-02，真实 Parser）

| 示例 | missing_fields | unknown_fields | 结果 |
|---|---|---|---|
| 完整投稿 | 无 | 无 | candidate |
| 缺作者投稿 | author | 无 | incomplete |
| 带注释投稿 | 无 | 无 | candidate，注释保留在正文 |
| 普通回复 | （非投稿楼层） | — | 不入队 |
| CRLF 行尾投稿 | 无 | 无 | candidate |
| 带未知字段投稿（[出处]） | 无 | 出处 | candidate，未知字段保留 |

## 明确保留人工、不写入公告的规则

- 来源优先级：多个来源冲突时怎么排序、以哪个为准——人工；
- 标签联动/标准化：标签要不要统一别名——人工；
- 多楼层合并：同一作品跨楼层合并——人工；
- 已入队稿件的后续修改：只提示人工复查，不自动覆盖。
